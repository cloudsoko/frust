# v1.0 Pain-Point Scorecard — Frust vs [[Frappe Pain Points]]

> The founding complaint, answered in its own words. On day one this vault
> opened by writing down 34 things wrong with Frappe. This is the acceptance
> test that document always was: every `P-x.x` scored **killed / bounded /
> open**, each verdict carrying a link into the evidence.

**The three rules this document lives by:**
1. **No verdict without evidence.** Untested is *open*, never killed-by-assumption.
2. **Bounded is honest.** A large bounded count is a two-week-old rewrite telling
   the truth about its edges, not a failure. `P-8.2` at 1.4× is *bounded*, and
   saying so is the point. (`P-8.1`'s per-database-restore bound was the other
   canonical example until WO-040 built the thing that lifted it.)
3. **No grade inflation.** A scorecard that scores everything killed is worth
   nothing. The entire value is that it can be trusted.

## Tally

**23 killed · 11 bounded · 0 open** (of 34) — *updated by [[2026-07-26 WO-024 load and footprint benchmark]] (P-1.4 open→killed, 60 MB measured), [[2026-07-26 WO-025 concurrent serve loop]] (P-1.1 bounded→killed: scales with cores), [[2026-07-26 WO-026 surrealdb write concurrency]] (**P-1.2 killed→bounded→killed in one day**: the probe caught Frappe's per-request-metadata-load mechanism reproduced in our own code, the verdict was downgraded honestly, then re-earned with a generation-invalidated cache and nine invalidation tests), and [[2026-07-28 WO-030 decimal for scripts]] (P-3.4 bounded→killed: the canonical bounded closed — `decimal.rs` exposed to the script host verbatim, three hosts one answer).*
>
> *The round trip P-1.2 took is the scorecard working exactly as designed: a comfortable verdict caught by the project's own probe, **downgraded before it was fixed**, and re-scored only against the evidence the downgrade demanded. A ledger that can move DOWN is the only kind whose UP means anything.*
>
> **[[2026-07-29 WO-040 chunk C namespace topologies]] closed P-8.1 (bounded → killed)** — and it is the bound WO-027 had *tightened against us* two days earlier. That is the round trip rule 2 exists to make possible: the DR probe made the verdict harsher with measured evidence, the tenancy build lifted it with **executed** evidence (export → drop → import, tenant A restored, tenant B's post-export write intact), and neither move was made on argument. **The kill is not total, and the row says so**: `single` still cannot promise restore-one, and its `backup_plan` reports `tenant_isolated: false` rather than implying otherwise — a killed verdict that still names what it does not cover.
>
> **[[2026-07-27 WO-027 backup restore DR]] moved no verdict** — deliberately. DR is an [[ADR-002 SurrealDB Lock-In]] adoption risk, not one of the 34 founding pains, and minting a row so a closed WO could score a *killed* is precisely the grade inflation rule 3 forbids. What the WO did produce was **evidence against us**: P-8.1's bound got *tighter* (export is per-database, v0 shares one — so no per-tenant restore), and P-7.1 gained the ops facts a deployment must budget for. A work order licensed to edit this document and using that licence only to make two verdicts *harsher* is the clearest test the ledger has passed.

That 12-bounded count is deliberate and load-bearing: it is where Frust is
honestly a *bounded* improvement, not a total one. Every bounded remainder
seeds the [v1.1 backlog](#v11-backlog-seeded-from-the-remainder) below. The lone
open (P-1.4, memory) closed the moment it was measured — which is exactly what
the open verdict was *for*.

> **[[2026-07-28 WO-030 decimal for scripts]] is the first v1.1 verdict to move**, and it moved by *building*, not re-scoring: the canonical bounded (P-3.4, the money footgun the whole project is a reaction to) is killed because `decimal.rs` now runs in the script sandbox verbatim — the same arithmetic in three hosts. This is the counterpart to WO-027's two-tighter-bounds: the ledger moves up only when the work earns it, and here the work earned it.

> [!warning] Every bounded verdict is now CLASSIFIED — see [[v2.0 Deployability Gate]]
> The v2.0 gate sorted all 12 bounds into **measurement / architecture /
> assumption**. Three were held up by nothing but the absence of a test
> (**P-2.2** multi-app hook composition, **P-7.3** major-upgrade survival, and a
> new Desk-tier concurrency gap), so **the gate does not pass** until they are
> measured. A `bounded` here is only trustworthy in the first two senses; read
> the gate for which sense each one is.

## The scorecard

### 1. Performance & Concurrency

| P | verdict | evidence |
|---|---|---|
| P-1.1 GIL & sync workers | **killed** (measured, WO-024 → fixed & re-measured, WO-025) | The GIL is gone *and the kernel no longer serializes*. WO-024 found the shipped loop single-threaded — flat ~15 req/s from 1→500 clients. WO-025 replaced it with a core-sized worker pool: throughput now **rises with concurrency and saturates at 48 req/s** (3.2× the serialized ceiling), p50 at 500 clients halved (21.9 s → 10.1 s). **The kernel is no longer the bottleneck** — hook dispatch measures 0.087 ms and SurrealDB burns ~10× the kernel's CPU (371.8 s vs 34.3 s), so the ceiling is now **DB write concurrency**, with the kernel's 16 workers idle behind it. That is the honest handoff, and it targets a later scale WO. [[2026-07-26 WO-024 load and footprint benchmark]] · [[2026-07-26 WO-025 concurrent serve loop]] |
| P-1.2 Metadata per request (~50-200ms) | **killed** *(downgraded to bounded 2026-07-26 when the WO-026 probe caught the mechanism, then **re-earned with evidence** the same day)* | **The mechanism is gone, not just the symptom.** The probe found metadata read from the DB on *every* request — Frappe's own pattern, invisible single-threaded, one-third of the concurrency ceiling once WO-025 parallelized. WO-026 removed it: a **generation-invalidated** metadata cache (not a TTL — every kernel-mediated metadata write bumps the generation, so a stale read is structurally impossible), plus the same for the session lookup. Per-request DB round trips **3 → 1**; throughput **48 → 124 req/s**, arithmetic tracking the prediction at every step; and the warm submit median fell **32 ms → 5 ms**, five times *under* REQ-6.1.1's 25 ms floor. Invalidation is proven by **nine tests** (sync, install, update, uninstall, per-doctype keying, instant logout, cross-session survival, hit-equals-miss, unknown-token refusal) — the gate this verdict was made conditional on. [[2026-07-26 WO-026 surrealdb write concurrency]] |
| P-1.3 ORM N+1 | **killed** | Child tables are *embedded* (one read, not N+1); reads compile a structured filter to a single query. [[ADR-008 Data Shape]] · [[2026-07-25 WO-015 child-table line editor]] |
| P-1.4 Memory footprint | **killed** (measured, WO-024) | The kernel is **60 MB resident** with the 1 M-row dataset loaded, growing to only **76 MB under 500-client load** — one process, no per-connection explosion, versus Frappe's 300-500 MB **per worker** × N workers. (SurrealDB holds ~960 MB for the 1 M rows — the data, which any DB pays.) The lone OPEN becomes a decisive KILLED. [[2026-07-26 WO-024 load and footprint benchmark]] |
| P-1.5 Crude optimistic locking | **killed** | Write conflicts retried transparently under a bounded budget; the raw DB wording never reaches users (ADR-007 hygiene). Conflict canary test. [[2026-07-24 Architecture skeleton (WO-002)]] |
| P-1.6 Single-threaded scheduler | **bounded** | Per-tenant fair scheduling stops cross-tenant starvation, but it is still one worker loop — a long handler blocks the tick. [[2026-07-25 WO-013 tenant fairness]] |

### 2. Architecture & Runtime

| P | verdict | evidence |
|---|---|---|
| P-2.1 No app isolation | **killed** | Plugins are WASM components; a hostile plugin (`spin`/`hog`) is force-terminated without killing the kernel, and cannot reach the DB except through the broker. [[2026-07-26 WO-017 item 2 worker watchdog containment]] · [[2026-07-26 WO-019 criterion 1 the door probe]] |
| P-2.2 Hooks are global mutable magic | **bounded** | Hooks are explicit, sandboxed, and trace-named (not opaque merging) — but multi-app hook composition across many installed apps is lightly exercised. [[2026-07-25 WO-010 Observability]] |
| P-2.3 Heavy polyglot stack | **killed** | Python+MariaDB+Redis×3+Node+wkhtmltopdf → **two processes** (Rust kernel + SurrealDB); realtime is in-kernel, no Node sidecar. (Print/PDF unbuilt — not yet a stack component.) [[2026-07-25 WO-012 Desk realtime]] |
| P-2.4 Realtime bolted-on Node sidecar | **killed** | Realtime is native, per-session, **permission-aware** (subscribes under the subscriber's own JWT); no Node, no Redis pubsub. Bound: ~20 subs/table budget. [[ADR-011 Realtime]] · [[2026-07-25 WO-012 Desk realtime]] |
| P-2.5 Dependency hell between apps | **killed** | Each WASM component links its own dependencies — shared-requirements resolution is eliminated by construction. [[ADR-005 Plugin Isolation]] |
| P-2.6 Restart-required changes | **killed** | The entire install/enable/disable/update/uninstall lifecycle runs **with no restart**, proven end to end by the demo app and the accounting seed. [[2026-07-26 WO-019 criterion 7 the demo app end-to-end]] · [[2026-07-26 WO-022 accounting seed]] |

### 3. Type Safety & Correctness

| P | verdict | evidence |
|---|---|---|
| P-3.1 Zero static guarantees | **bounded** | The kernel and the wire contract are statically typed (typed `Value` envelope), killing whole classes of stringly-typed bugs — but app-level DocType fields remain string-keyed metadata, so a field rename can still break an app script at runtime. [[ADR-006 Plugin Capability Surface]] |
| P-3.2 Validation scattered across 4 layers | **killed** | Validation has defined, non-overlapping homes: the one permission compiler, the one lattice EVENT, explicit hooks — and the invariant split (row-permission gates *who*, lattice gates *which docstatus*) is proven to compose without disagreeing. [[ADR-009 Execution Model]] · [[2026-07-26 WO-020 row-write permission]] |
| P-3.3 Silent failure culture | **bounded** | Structural wins are real — no `ignore_permissions` flag exists (the DB enforces under the caller's session), writes that change nothing return typed errors — and this milestone converted **three** silent failures to loud ones. But "no silent failure" is a discipline, provable only by ongoing vigilance. [[2026-07-26 WO-020 row-write permission]] |
| P-3.4 Float-based money | **killed** *(bounded→killed 2026-07-28, WO-030)* | Money is decimal at storage, transport, kernel computation, rollups **and now script computation** — the float door is shut at every boundary. The last bound (scripts had no exact-decimal helper and hand-rolled it — the seed's own first script tripped on `0.335`) is closed: the Boa host gets a `Decimal` binding that is **`decimal.rs` compiled into the sandbox verbatim**, not a JS reimplementation, so the byte-equal reconciliation now spans **three hosts (script/kernel/DB), one answer** — proven, including the `0.335` case that bit the PM. The seed's hand-rolled math is deleted; the WO-017 float-catch still fires (the safe path is *added*, the guard not removed); containment holds (pure arithmetic, no new capability). Both shared-artifact surfaces carry it (kernel + browser engine rebuilt). [[2026-07-28 WO-030 decimal for scripts]] · [[2026-07-26 WO-016 decimal rollup accumulation]] · [[2026-07-26 WO-021 money arithmetic]] · [[2026-07-26 WO-022 accounting seed]] |

### 4. Schema & Migrations

| P | verdict | evidence |
|---|---|---|
| P-4.1 Fragile schema sync | **killed** | Each resource's DDL + history commit atomically; a failed resource rolls back fully while prior ones stand; the run collects all errors and a re-run resumes idempotently. [[2026-07-24 Module 3 close — sync engine port + rollback position]] |
| P-4.2 Customizations vs fixtures vs patches | **killed** | One mechanism: metadata records. Apps ship metadata in a bundle — no Custom Field vs Property Setter vs fixtures vs patches precedence war. [[2026-07-26 WO-019 criterion 2 the manifest]] |
| P-4.3 Renames are destructive | **bounded** | The destructive-change gate refuses a silent field-drop in production, so a rename can never *silently* lose data — but rename-as-a-first-class data-preserving operation isn't built (you add-new, backfill, drop-old under the gate). [[2026-07-24 Module 3 close — sync engine port + rollback position]] |
| P-4.4 No versioning/rollback/dry-run | **killed** | Dry-run preview shipped as install UX; schema revert to recorded snapshots, gated identically to forward migration and recorded as a forward event. [[2026-07-26 WO-019 criterion 3 the install story]] |

### 5. Security

| P | verdict | evidence |
|---|---|---|
| P-5.1 Server Scripts are sandboxed `eval` | **killed** | Tier-2 scripts run in a WASM/Boa sandbox with a **proven-empty** capability surface (hostile probe: no fetch/fs/network/globals) and forcible termination; there is no `eval` path, ever. [[2026-07-26 WO-017 item 2 worker watchdog containment]] · [[2026-07-26 WO-017 item 3 decimal NaN-catch]] |
| P-5.2 Raw SQL escape hatch | **killed** | Query text is confined to allowlisted kernel modules (CI-enforced by `surql_monopoly`); plugins/scripts cannot *express* raw SQL — it is un-representable, not filtered. [[2026-07-26 WO-019 criterion 1 the door probe]] |
| P-5.3 Permission model complex yet leaky | **killed** | One permission compiler; row security enforced **by the DB under the caller's own session** (not opt-in SQL fragments), proven byte-equal across every door — broker, REST, plugin route. Bound: `allow_on_submit` field-level path deferred. [[ADR-012 Row-Write Permission]] · [[2026-07-26 WO-019 criterion 4 routes over REST]] |
| P-5.4 Audit trail best-effort | **killed** | Audit is the changefeed — a property of storage, unbypassable by any actor (every lifecycle action lands there by virtue of being a write). Bound: changefeed retention is finite. [[2026-07-26 WO-019 criterion 3 the install story]] |

### 6. Background Jobs & Async

| P | verdict | evidence |
|---|---|---|
| P-6.1 RQ fire-and-forget | **killed** | Jobs are DB records with at-least-once delivery, surviving worker crashes — 3,200/3,200 delivered across a mid-subscription restart. [[2026-07-24 Live-query and event fidelity (WO-004)]] |
| P-6.2 No idempotency/exactly-once | **bounded** | At-least-once with re-derived authority and the primitives for idempotency are provided — but exactly-once is *not* claimed; idempotency is the handler's contract, provided-for not enforced. [[ADR-009 Execution Model]] |
| P-6.3 Queue starvation | **bounded** | Per-tenant fair scheduling prevents cross-tenant starvation (1.4× bound) — but priority/class routing *within* a tenant isn't built; a long job can still delay a short one on the same round. [[2026-07-25 WO-013 tenant fairness]] |

### 7. Developer & Operator Experience

| P | verdict | evidence |
|---|---|---|
| P-7.1 Bench is a house of cards | **bounded** | The bench machinery is simply gone (two processes, no symlinks/supervisor/nginx/sites-dir) — but production deployment packaging isn't built; it is `frust serve` + surreal, dev-run. **DR is now procedure, not packaging** (WO-027): a *tested* backup/restore runbook exists and the kernel refuses to serve a restored store with a compromised key, but there is no `frust backup`/`frust restore` command, no scheduling, and no supervision — the operator runs `surreal export` on their own cadence. Two ops facts a deployment must budget for: an accepting boot takes **~25 s** (a 5 s health check calls a working kernel dead) and RPO **is** the export interval. [[2026-07-24 Module 6 + WO-005 close — frust serve]] · [[DR Runbook]] |
| P-7.2 Testing slow and stateful | **bounded** *(bounded-by-MEASUREMENT — number sharpened 2026-07-28)* | Test isolation was actively fixed this milestone (self-seeding per-test DBs; the ambient-fixture landmine removed) — but the suite is slow: **919 s (15.3 min) across 43 binaries, slowest binary 82 s**, measured at the v2.0 gate (the old ">10 min" was an estimate). Perf gates are substrate-sensitive and need a dedicated scratch store. [[2026-07-26 WO-020 row-write permission]] · [[v2.0 Deployability Gate]] |
| P-7.3 Upgrade pain | **bounded** | The mechanisms exist — versioned bundles, gated diffs, and plugin-compat that fails at **load-link time, loudly, not at runtime** — but Frust has no multi-version upgrade history to prove apps survive a real major upgrade. Untested by time. [[2026-07-26 WO-019 criterion 1 the door probe]] |
| P-7.4 Weak observability | **killed** | Structured logging, distributed tracing, a Prometheus `/metrics` endpoint, per-tenant attribution — and it extends to third-party surface (plugin routes carry app-named spans). "Missing entirely" in Frappe; fully built here. [[2026-07-25 WO-010 Observability]] |
| P-7.5 Legacy Desk UI coupling | **killed** | The Desk is a **pure REST client** over the same documented surface any client uses — no privileged internal API to reverse-engineer. Bound: the Desk is minimal (forms/lists/child-tables; no print/report-designer). [[2026-07-25 WO-009 Desk v1]] · [[ADR-004 Topcoat for Desk v0]] |

### 8. Multi-tenancy

| P | verdict | evidence |
|---|---|---|
| P-8.1 Site-per-directory tenancy | **KILLED** *(2026-07-29, WO-040 chunk C — was bounded; bound had been TIGHTENED 2026-07-27 by WO-027)* | Tenancy topology is a **runtime-selected strategy**: one binary serves `single`, `database-per-tenant`, `namespace-per-tenant` or `namespace-per-tenant-env`, chosen by config, all through one guarded seam. Frappe's costs are gone — one schema-deploy path, shared connections, no per-site cold caches, and **one process serving N tenants** (median **138 req/s at c=10** with per-request routing in the path; footprint flat at ~65 MB across 1/10/50 tenants). **The bound WO-027 tightened is lifted with executed evidence:** per-tenant restore is operational *through the strategy* — tenant A exported, corrupted, dropped and re-imported while tenant B kept a write made **after** the export ([[2026-07-29 WO-040 chunk C namespace topologies]], `tenant_restore_ops.rs`); whole-instance = enumerate the registry. **Two residual facts, recorded rather than hidden:** `single` still cannot promise restore-one and its `backup_plan` **says so** instead of implying otherwise; and `surreal import` is **additive, not restore-over**, so the real procedure is export → **drop the target database** → import. [[ADR-003 Tenancy Model]] · [[DR Runbook]] · [[2026-07-27 WO-027 backup restore DR]] |
| P-8.2 No tenant resource isolation | **bounded** | Per-tenant verb throttling + fair scheduling bound the noisy-neighbour effect to a **measured 1.4×** (not eliminated); shared-DB compute isolation is explicitly out of scope and would re-open ADR-003. The canonical bounded. [[2026-07-25 WO-013 tenant fairness]] |

## What Frappe gets right — preserved, and not-yet

Frappe's strengths the rewrite had to *keep*:

- **Metadata-driven everything** — ✅ kept and proven: the accounting seed is entirely metadata. [[2026-07-26 WO-022 accounting seed]]
- **Zero-to-CRUD speed** — ✅ a DocType in a bundle generates schema + REST + Desk form + permissions, no code.
- **Docstatus lifecycle** — ✅ kept as the one DB-tier invariant (the lattice EVENT). [[ADR-009 Execution Model]]
- **Customization without forking** — ✅ apps layer over core as bundles; the seed touched no core.
- **Batteries included** — ⚠️ **not yet**: email, print formats, a report designer, files/comments/assignments are unbuilt. This is the largest v1.0→v1.1 product gap, distinct from the pain points.

## The verdict

**Is Frust a Frappe replacement?** For the pains that drove the rewrite —
isolation, security, observability, money correctness, no-restart extension,
audit, jobs — **yes, and provably**: 22 of 34 killed with evidence, the
security section (P-5.x) a clean sweep, money correctness now a clean sweep too
(P-3.4 killed, WO-030), the founding architectural complaints (GIL-forced
concurrency, bolted-on realtime, restart-required changes, leaky permissions,
best-effort audit) structurally answered.

**Where isn't it yet?** The 12 bounded say it plainly: it cannot restore one
tenant without restoring all of them (P-8.1), has no production deployment
packaging (P-7.1), still runs one scheduler loop (P-1.6), and has none of the
batteries (email/print/reports) that make Frappe turnkey. It is a correct,
secure, observable, honest **kernel and platform** — two weeks old, telling the
truth about its edges — not yet a turnkey ERP.

*(The two verdicts this paragraph used to name — serving concurrency and
unmeasured memory — were killed by WO-024/025/026. It said "has never had its
memory measured" for a day after the measurement existed. Prose drifts from the
table it summarises; the table is authoritative.)*

That distinction is the whole point of this document, and Frust can now defend
both halves of it with a link.
