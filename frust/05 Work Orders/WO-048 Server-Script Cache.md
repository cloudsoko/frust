# WO-048: Server-Script Cache — Zero Root Calls on the Write Path

## Why

WO-047's census: the steady-state write path carries exactly **one** root call — `SELECT server_script FROM doctype WHERE name = … LIMIT 1` (`sync::load_server_script`), uncached, per validate, **running even for scriptless doctypes** because the query is how you find out. Collapsing it buys: JWT mode −297 µs and −1 round trip per write; **Basic escape-hatch mode −16.5 ms per write** (where it genuinely hurts); scriptless doctypes skip entirely; and the clean architectural property — **zero root round trips on the steady-state write path.** WO-026-shaped, machinery proven, invalidation site already bumps the generation.

## Exit criteria

1. **Cache `server_script` per `(tenant, doctype)`, generation-invalidated** — ride the existing WO-026 meta-cache machinery (a script is a field on the doctype record; consider carrying it in the cached `DocTypeMeta` rather than a second cache — pick the lazier shape that stays correct). No TTL: generation-bump only, same as the doctype cache.
2. **Correctness gated FIRST, WO-026 order:** ADR-007's live-mutability is a *ratified property* — script save → **next write** runs the new text, no restart. The WO-019 c6 test already pins this; it must stay green *against the cache* (it is the cache's failing control — confirm it goes red with invalidation deliberately broken, then restore). Uninstall/disable must refuse-from-cache, not serve a detached script (the WO-026 dangerous direction, re-proven here).
3. **Every invalidation site verified:** `POST /doctype/{name}/script` (WO-047 confirmed it bumps), schema sync, app install/update/disable/uninstall. A site that mutates script state without bumping is the defect; enumerate and test.
4. **Then the number:** per-write root calls 1 → 0, shown by the WO-047 trace method (same instrument, confound-free); scriptless-write cost measured. Report honestly if throughput doesn't move — at ~555 req/s the path is DB-bound elsewhere, and this WO's claim is the *property*, not a headline.
5. **Both auth modes** — the WO-047 lesson is one WO old: a test only ever run one way is unproven the other way. The suite runs green in jwt *and* basic.
6. Full hygiene: fresh-store perf gates, no regression (53 binaries / 330 / 0 baseline), scratch dropped.

## Boundaries

- The idle tickers (5.0/s `claim_next` + 4.0/s `MailWorker.queued_ids`, both named by WO-047) are **out of scope** — 9/s at 297 µs is ~2.7 ms/s, benign; polling-to-LIVE conversion is a separate conversation if ever justified.
- No change to the script pool's text-comparison semantics (WO-019 c6) — the cache feeds it, doesn't replace it.
