# WO-047: Hygiene Bundle

## Why

Three watch items have accumulated their justification. Small bundle, one session — the WO-033 shape.

## Items

1. **Fix the `kernel_hygiene::revoke_kills_` parallel flake at root cause.** Pre-existing (WO-044 proved it not-theirs: jwt 2/5 fail, basic 3/5, serial 0/5). A flaky test corrodes the project's most load-bearing signal — "0 failed" must mean 0 failed, or every future WO's tally carries an asterisk. Diagnose the actual interference (shared state? session-cache generation raced by a parallel test? timing?) and fix *it*. **Serializing the test is the last resort, taken only if the interference is itself by-design** (e.g. the global generation bump legitimately touches every session) — and then the serialization carries a comment naming why. Don't weaken the assertion to stop the flap.
2. **Commit the CSS referenced-vs-defined guard as a permanent check.** Two catches in two WOs (`--fui-space-*`/`--fui-font-sans` in WO-042, `--fui-outline` in WO-046) — recurrence is the promotion criterion WO-042's own caveat set ("grep if it recurs"). Make it a committed Desk-local check (a `pnpm` script or unit test scanning `frust_ui.css` + the Rust view code for referenced-vs-defined custom properties, and — since WO-046's finding was a *selector*, not a property — consider whether class-names-referenced-vs-defined is cheap enough to include; if it isn't, say so and ship the property half). The monopoly-guard pattern: it has caught its author twice; wire it so it can't be skipped.
3. **Name WHICH root calls remain — report, don't redesign.** WO-044 measured ~3 root calls per write and 19/s from the idle ticker, and explicitly didn't claim which. Identify them (the `frust_root_calls` metric + a trace read should suffice — measurement, not archaeology). Deliverable is the *list with call sites*. Collapsing any of them (WO-026-style cache) is a separate decision for the PM with the list in hand — cheap now at 297 µs each, so the bar for touching them is low urgency, high confidence.

## Exit criteria

1. Full kernel suite green **in parallel, 5/5 consecutive runs** — the flake's own falsifying instrument, run both auth modes.
2. The CSS guard committed, wired into a runnable check, and its failure mode demonstrated once (plant an undefined property, watch it fail — the WO-032 rule: a check you've never seen fail is decorative).
3. The root-call list with call sites in the build log; PM decision queued if any collapse looks warranted.
4. Zero behavior change outside the flake fix; regression suites green.

## Boundaries

- No perf claims (nothing here should move a number; if fixing the flake changes any timing-adjacent code, say so).
- Item 3 is *identification only* — no cache, no invalidation design, no redesign inside a hygiene bundle.
