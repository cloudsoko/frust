## Criterion 1 — THE DOOR PROBE, before any registry design

REQ-2.2.2 threatens a third path to the database. PM prediction, stated to be falsifiable: **a plugin route handler is a profile of ADR-006** — a WIT export receiving the verb surface under the *caller's* session, in a world with no db handle to obtain. Probe it: implement one route handler this way, attempt hostile escape (raw query, connection reuse, root leak), confirm `surql_monopoly` and the one-permission-compiler property survive with the route live. **If the shape fails, stop — the registry design is wrong, and that's a PM conversation.**

> [!success] Criterion 2 DONE 2026-07-26 ([[2026-07-26 WO-019 criterion 2 the manifest]]) — gate discipline reused literally (plan/apply = one call shape differing only by `MigrationOptions`); reserved workflow slot round-trips verbatim; 9-errors-one-pass validation; half-installed-app and ghost-hook-point classes caught at validation; numeric versions, `None` not silent-`false`; `app.rs` query-free outside the allowlist.

> [!note] PM ruling (2026-07-26) — the app registry is a **kernel-owned, write-closed DocType** (fourth member of the pattern: rollups WO-007, `app_user` WO-008, `_tenant_policy` WO-013). DDL from `meta.rs`, boot re-asserted; mutations only through the kernel install path under manager auth — not expressible through the compiled write door at all; reads via broker (queryable, permission-compiled, changefeed-audited, free Desk list view). Circularity dissolved: the compiler governs who *sees* the registry, never what *mutates* it. `app.rs` stays query-free; no allowlist grows.

> [!success] Criterion 3 DONE 2026-07-26 ([[2026-07-26 WO-019 criterion 3 the install story]]) — 30 binaries green. Install = validate→plan→gate→apply→registry, no step after a refusal; disable detaches without data loss (asserted by row count AND value); enable restores exact script text from the stored manifest (**the registry is the system of record for what an app is**); destructive update refused *naming its casualty* (`REMOVE FIELD memo`, field verified intact); double-install refused pointing at update; 5 changefeed entries for 4 actions (audit as a storage property); clerk 403 on every app route. Meta v2→v3 **exercised on the real dev DB**: refuse-then-accept, login survives, **no JWT rotation** (`access_ddl` untouched — verified by behavior, not memory). ⚠️ Ops caveat banked: an *accepting* boot took ~25 s (migration + full sync) before REST listens — a health check probing early will kill a working kernel; budget the time.

## Remaining Criteria

2. **The manifest:** an App = versioned bundle — DocTypes, workflows (schema reserved for WO-018), client scripts, named queries, route declarations, `.wasm` components, aggregate declarations. One file format, validated before anything applies (the sync engine's gate discipline extends to bundles).
3. **Install / enable / disable / update through the Desk** (manager-tier): install runs the sync engine (dry-run preview shown first — REQ-6.6.1 becomes UX); disable detaches hooks/routes/scripts without data loss; update = diff + gate, destructive changes refused per REQ-6.6.2; every action audited.
4. **Registered routes serve** under bearer discipline, trace-spanned, tenant-attributed, door-throttled (WO-013 budgets apply to plugin routes automatically — prove it, since they must not be a throttle bypass either).
5. **Uninstall is honest:** state what it does and doesn't remove (metadata detached, data tables remain per REQ-6.6.3's revert≠restore line) — the Frappe `bench remove-app` horror story, answered in writing.
6. **Server-script delivery (added 2026-07-26 from WO-017 item-3 finding):** the kernel has never run a per-DocType script — `WasmHooks` builds an empty WASI env (correct posture: inheriting leaks kernel secrets) and nothing plumbs `client_script`/server scripts to the engine. This WO builds the delivery: hook dispatch loads the script text for (doctype, hook-point) from metadata per call (pooled per ADR-007's `(tenant, script-set)`), via a deliberate seam — not env inheritance. ADR-007's "scripts are data, live-mutable" becomes true server-side, not just proven-in-principle.
7. **The proof:** a demo app (small — one DocType, one hook, one route, **one server script that demonstrably runs**, one client script) installed from a bundle file through the UI, exercised, disabled, re-enabled, updated to v2 with a field addition — no restarts anywhere.
