# WO-050: Extension Mechanism

## Why

ADR-015 is ratified; this builds it. **The binding sequence is the ADR's own ruling: the mechanism lands before the boundary moves** — `owns` is relaxed as the *last* criterion, behind everything below, because WO-049 proved a naive relaxation enables silent override (owner's hook replaced, no error, no trace), not composition.

## Exit criteria — in build order

1. **Storage:** `server_script` scalar → **list of `{app, script}`** on the doctype record — a `DocTypeDef` change under ADR-008 migration discipline (meta bump, existing scalar migrated as the owner's entry, recompute-not-launder posture).
2. **Dispatch:** owner-first, un-overridable loop — the owner's hook always runs first and cannot be replaced or skipped by any extension. **The permanent failing control is WO-049's own silent-override scenario:** the probe's B-replaces-A case re-run against the shipped dispatch must show `owner_ran = "A"` *and* `ext_ran = "B"` — and the test goes red if the owner's hook is ever displaced. Extension order after the owner: deterministic (install order), recorded, boring.
3. **Keys widened:** script pool *and* the WO-048 cache go `(tenant, doctype)` → `(tenant, doctype, app)`. WO-048's correctness suite re-run against the widened key (generation invalidation per entry; uninstall-refuses-from-cache per app — the dangerous direction, per-app now).
4. **Attribution:** `app` lands on the `hook_dispatch` span — "which app changed this behavior" is a log field. P-2.2's archaeology answer, made checkable: the trace test asserts the extension's hook carries the extension's app, not the owner's.
5. **Veto semantics as ruled:** an extension's `Err` rejects the write, typed, **naming the rejecting app** in the error the caller sees. No suppression mechanism. The owner's rejection still wins first (it runs first).
6. **Envelope loudness (the probe's unpredicted finding):** an extension writing a field it did not declare = **typed, loud error** — never silent stripping. Test: the probe's own NEITHER-ran instrument-error scenario becomes the regression (undeclared write → `E_FIELD_UNDECLARED`-class refusal naming field and app).
7. **Manifest + registry:** extension declarations (namespaced fields + hooks on foreign doctypes) as manifest content — WO-019 gate discipline literally (validated, plan-shown, refused loudly); per-app registry rows; **conflicts = install-time refusal naming both apps** (refuse-ambiguity as ruled); **uninstall of the extension detaches its fields and hooks, the owner's doctype and data untouched** — honest-uninstall extended, asserted both directions.
8. **Owner evolution — wire the seam WO-049 named:** on owner update, the plan consults other apps' stored manifests against the new schema; an update that breaks a declared extension surface **refuses naming the extension casualty** ("this update breaks extension E of app B — reads `Y.z`, which you removed"), acknowledge path per WO-019's destructive-update shape. Never silent-disable. Test: owner renames a field an extension declared → refusal with both names in it.
9. **THEN `owns` relaxes** — declared extensions pass, undeclared hooking still refused with the A1 message. The relaxation commit is the last one, and the full suite (both auth modes) is green before and after it.
10. **The dogfood proof, live:** a second real app extends the accounting seed — adds a namespaced field + a validate hook to an owner doctype — installed through the shipped path, exercised in the browser (tested-seam≠wired), uninstalled cleanly. **P-2.2 re-scored** on the scorecard with this as evidence (bounded → the grade the evidence earns; the trade line updated from "not possible" to the new truth).

## Boundaries

- **Vocabulary widening (OnWrite/Scheduled delivery) is OUT** — ADR-015 ruled it ordinary REQ-2.2.1 build work, but it's its own follow-on; composition lands on `validate` first. Don't balloon.
- Extension-to-extension dependencies, marketplace ordering: out (evidence-gated, per the ADR's v1 scope).
- Standing hygiene: fresh-store perf gates (the dispatch loop touches the write path — floor + tax re-measured), both auth modes, scratch dropped, monopoly guards untouched-or-extended (never widened for convenience).

## Escalation

- If the widened pool key or the dispatch loop moves the 25 ms floor or the write ceiling measurably, report the number before trading — the remedy conversation is the PM's.
- If the scalar→list migration can't preserve WO-019's enable-restores-exact-text property, stop and report — that's an ADR-008-shaped migration question, not an improvisation.
